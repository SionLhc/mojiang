# 剧情编排画布 · 规划

> 状态：待开发
> 目标版本：v0.2
> 定位：**让作者看见自己的剧情结构，并让 AI 对此给出可定位的判断**

---

## 1. 为什么做这个

现在作者理剧情的方式是写细纲，也就是线性 Markdown。它有两个问题：

1. **看不出结构**：三条支线交叉推进时，文档里只是交替的段落，看不出哪条断了、哪条挤在一起
2. **看不出问题**：连续三个转折、埋了没回收的线、主角消失五章，这些在纯文本里要人肉数

节点图画布解决第一个问题；AI 诊断解决第二个。两者缺一不可——只有画布是好看的白板，只有 AI 是空口评价。

**不做**：通用白板、流程图工具、思维导图。节点必须绑定小说语义（剧情/伏笔/人物/章节）。

---

## 2. 用户故事

| 场景 | 期望 |
|---|---|
| 想第二卷主线 | 双击空白新建节点，拖拽排列，拉线表示因果，写完能整体看一遍 |
| 检查伏笔 | 伏笔节点自动来自 `伏笔.json`，埋在哪、回收没，一眼看出 |
| 找问题 | 点"AI 诊断"，节点依次被扫描，结果逐条出现，有问题的节点呼吸高亮 |
| 追一条建议 | 点某条建议，相机飞到相关节点，而不是让我自己找 |
| 回到正文 | 双击绑定了章节的节点，直接跳到那一章 |

## 3. 数据模型

存 `书库/{书名}/剧情.json`。纯数据，不依赖 UI。

```ts
/** 节点类型，决定配色和语义 */
export type PlotNodeKind =
    | 'setup'      // 铺垫
    | 'turn'       // 转折
    | 'climax'     // 高潮
    | 'foreshadow' // 伏笔
    | 'suspense';  // 悬念

export interface PlotNode {
    /** 短 id，n1 / n2 …… 用于连线和 AI 引用 */
    id: string;
    kind: PlotNodeKind;
    title: string;
    /** 一两句话，写清这场戏发生了什么 */
    summary: string;
    /** 关联的人设卡名字，和 人设/*.md 的文件名一致 */
    characters: string[];
    /** 绑定章节号，双击跳转；不绑就是纯构思 */
    chapter?: number;
    /** 伏笔节点关联的 伏笔.json item id */
    foreshadowId?: string;
    x: number;
    y: number;
}

/** 连线语义 */
export type PlotEdgeKind =
    | 'cause'      // 因果推进（A 导致 B）
    | 'parallel'   // 平行推进（同时间的两条线）
    | 'foreshadow';// 伏笔关联（埋 → 收）

export interface PlotEdge {
    id: string;
    source: string;
    target: string;
    kind: PlotEdgeKind;
    /** 连线上显示的文字，如"真相揭晓" */
    label?: string;
}

export interface PlotGraph {
    nodes: PlotNode[];
    edges: PlotEdge[];
    updatedAt: string;
}
```

**约束**：

- 节点 id 一旦生成不再变（AI 建议要引用它）
- 删除节点时连带删除相关连线
- `foreshadowId` 只允许指向已存在的伏笔，否则降级为普通节点并在界面标黄

## 4. 交互规范

### 画布

| 操作 | 行为 |
|---|---|
| 双击空白 | 在该位置新建"转折"节点并进入标题编辑 |
| 拖拽节点 | 移动，松手存盘（防抖 500ms） |
| 节点边缘圆点拖出 | 创建连线，落到目标节点 |
| 滚轮 | 以光标为中心缩放 |
| 空格 + 拖拽 / 中键拖拽 | 平移画布 |
| 选中节点按 Delete | 删除（连带连线） |
| Ctrl+Z | 撤销（保留最近 50 步） |

### 节点卡片

```
┌────────────────────────┐
│ ▌转折                  │  ← 左侧 3px 色条
│ 消失的第七位乘客        │  ← 标题，14px 加粗
│ 船票六张，乘客却称只有  │  ← 摘要，13px，最多三行
│ 六人                   │
│ ─────────────────────  │
│ ＋顾舟  ＋无名乘客      │  ← 人物标签，来自人设卡
│ 第 3 章                │  ← 绑定章节时显示
└────────────────────────┘
```

- 宽度固定 240px，高度自适应
- 选中：玉色描边 + 轻微上浮
- 有 AI 问题：边框呼吸

### 顶部栏

- 左：项目名 / 视图切换（主线 · 全部 · 只看伏笔）
- 中：`+ 剧情` `+ 伏笔` `AI 诊断`
- 右：`N 个节点 · M 条关系`

### 左下角

缩放控件：`−` `100%` `+` `重置视图`

## 5. 动画规范

**原则**：每个动画都要回答"它在帮用户理解什么"，否则不加。

| # | 元素 | 触发 | 时长 | 曲线 | 作用 |
|---|---|---|---|---|---|
| 1 | 节点出现 | 新建 / 从细纲导入 | 220ms | spring(stiffness 300, damping 24) | 确认操作生效 |
| 2 | 连线生长 | 新建连线 | 400ms | ease-out，stroke-dashoffset: len → 0 | 看清连到哪个节点 |
| 3 | 因果线流动 | 常态（≤200 节点时） | 1.2s 循环 | linear，dashoffset 位移 | 区分因果与平行 |
| 4 | AI 扫描 | 点「AI 诊断」 | 每节点 180ms，依次 | scale 1→1.04→1 + 玉色光晕 | 让用户看到 AI 在读什么 |
| 5 | 结果卡片 | 诊断返回 | 260ms，逐条 stagger 60ms | ease-out，y+12→0，opacity 0→1 | 一条条看，不糊成一团 |
| 6 | 问题节点 | 有 finding 指向 | 2s 循环 | 边框透明度 0.4↔1 | 一眼找到病灶 |
| 7 | 相机飞行 | 点某条建议 | 600ms | easeInOut，fitView(padding 2) | 从结论跳到现场 |

**性能降级**：节点数 > 200 时，关闭 #3 和 #6，只保留静态色。React Flow 在 500 节点以内保持 60fps，超过要虚拟化（本期不做，改为提示"节点过多，建议拆分视图"）。

## 6. AI 诊断设计

### 6.1 输入序列化

只给结构，不给原文。原文太长且没必要。

```
【剧情节点】
[n1] 铺垫 | 末班渡船 | 顾舟收到信，午夜登上最后一班渡船 | 人物：顾舟
[n2] 转折 | 消失的第七位乘客 | 船票六张，乘客却称只有六人 | 人物：顾舟、无名乘客
[n3] 高潮 | 对岸十年前的自己 | 船停靠在记忆里的旧码头 | 人物：顾舟、无名乘客

【关系】
n1 → n2（因果推进）
n2 → n3（真相揭晓）
n3 → n4（平行推进）

【统计】
节点 7 个，其中转折 3 个、铺垫 1 个、高潮 1 个、伏笔 2 个
人物出现：顾舟 6 次、无名乘客 2 次、渡船老人 1 次
```

### 6.2 系统提示（固定）

```
你是剧情结构分析器。用户给你一张剧情节点图，你只能基于给出的节点和连线分析。

硬规则：
1. 只能引用给出的节点 id，不得编造不存在的节点
2. 每条结论必须用 nodeIds 指明涉及哪些节点，否则不要输出
3. 不写"建议增加冲突""节奏可以更紧凑"这类空话，必须说清在哪两个节点之间、加什么、为什么
4. 没发现问题的维度不要硬凑，findings 可以是空数组
5. 只输出 JSON，不要任何解释文字

评分：structureScore 0-100，只反映结构完整度（因果链是否闭合、节奏是否有起伏、伏笔是否有回收），不评价文笔。
```

### 6.3 输出 schema

```json
{
  "structureScore": 62,
  "findings": [
    {
      "kind": "pacing",
      "severity": "warn",
      "nodeIds": ["n1", "n2", "n3"],
      "message": "n1→n2→n3 连续三次升级，中间没有一处喘息",
      "suggestion": "在 n2 之后插一个铺垫节点：交代顾舟为什么非上这条船不可，让读者先松一口气再进高潮"
    }
  ]
}
```

`kind` 限定枚举：

| kind | 含义 |
|---|---|
| `pacing` | 节奏问题：连续同类节点、长时间无起伏 |
| `broken-chain` | 断链：埋了没回收、因果链断了 |
| `weak-cause` | 因果薄弱：连线两端缺少动机支撑 |
| `absence` | 人物缺席：主角连续多节点未出现 |
| `climax-position` | 高潮位置失衡：过于靠后或过于密集 |
| `branch-overload` | 支线过载：支线数量超过主线承载 |

### 6.4 校验与兜底

| 情况 | 处理 |
|---|---|
| 输出不是 JSON | 尝试提取 ```json 代码块，再不行取第一个 `{` 到最后一个 `}` |
| 解析仍失败 | 原样展示模型输出，标注"格式不合规，未采纳"，不假装成功 |
| nodeIds 里有不存在的 id | 丢弃该 id；全都不存在则整条 finding 丢弃 |
| findings 为空 | 正常显示"未发现结构问题"，不补造问题 |
| 花费超预算 | 走现有预算拦截，先问作者 |

**所有丢弃都要记日志**，累积下来能看出模型哪里不听话，用来改 prompt。

### 6.5 入口

- 顶部 `AI 诊断` 按钮：整图分析
- 选中节点后右键：`只分析这场戏`
- 首次使用时提示"这次会花约 ¥0.02"，用现有成本预估

## 7. 分期与验收

### P1 · 画布骨架（2 天）

- [ ] React Flow 接入，点阵背景，缩放平移
- [ ] 新建/编辑/删除节点，拖拽，撤销
- [ ] 拉线、连线标签、三种连线语义
- [ ] 存 `剧情.json`，重开能还原
- [ ] 动画 #1 #2 #3

**验收**：能在一张画布上排出 15 个节点、12 条连线，关掉应用重开，位置和连线完全一致。

### P2 · 类型与视图（1 天）

- [ ] 五种节点配色 + 图标
- [ ] 顶部统计、视图切换（主线/全部/只看伏笔）
- [ ] 人物标签展示与点击聚焦

**验收**：30 个节点的图里，能只看某个人物参与的节点。

### P3 · AI 诊断（1.5 天）

- [ ] 序列化 + prompt + 结构化解析 + 兜底
- [ ] 扫描动画、结果卡片、问题节点高亮、相机飞行
- [ ] 三种 kind 的图标与文案

**验收**：故意造一个"三个连续转折 + 一条断链"的图，AI 必须报出这两类问题且 nodeIds 正确；把图改成合理结构后，它不能硬凑问题。

### P4 · 数据联动（1.5 天）

- [ ] 伏笔节点同步 `伏笔.json`（增删改双向，注意冲突策略）
- [ ] 节点绑定章节，双击跳转
- [ ] 从细纲批量导入节点

**验收**：在画布上新建伏笔节点，`伏笔.json` 里能查到；在伏笔界面删除，画布上消失。

## 8. 技术选型

| 需求 | 选择 | 理由 |
|---|---|---|
| 节点图 | `@xyflow/react`（React Flow 12） | 拖拽/连线/缩放/自定义节点全是现成的，社区方案最成熟 |
| 动画 | `framer-motion` | 布局动画、列表 stagger、相机过渡，手写 FLIP 容易出错 |
| 状态 | 现有 zustand store + 一个 `plotSlice` | 不引新状态库 |
| 存储 | `剧情.json`，走现有 `writeJsonFile` | 和账本、伏笔同一套 |

**体积影响**：React Flow ~100KB、framer-motion ~50KB（未压缩）。Electron 本地加载，可接受。

**不选**：自己写 Canvas 渲染（交互细节太多）、tldraw（偏白板，节点语义要重写）、X6（更偏流程编排，React 集成不如 RF 顺）。

---

## 9. 明确不做

- 自动生成整本剧情（AI 一次性造 50 个节点没有意义，作者不会看）
- 多画布 / 图层 / 分组（第一版一个画布够用）
- 协同编辑
- 导出为图片（P4 之后再说，优先级低）
- 节点里嵌正文全文（摘要就够，点进去看正文）

---

## 10. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 画布很酷但作者不用 | 白做 | P1 做完先给作者用一周，用不上就停 |
| AI 只会说空话 | 核心价值归零 | prompt 里禁止套话 + 验收标准里明确"不能硬凑" |
| 节点多了卡 | 体验崩 | >200 节点降级动画；>500 提示拆分 |
| 与伏笔数据双写冲突 | 数据错乱 | 明确 `伏笔.json` 是唯一数据源，画布只是视图，不做反向写入（P4 再定） |
