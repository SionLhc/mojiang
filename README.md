# 墨匠

本地运行的写作与笔记工作台。**能写小说，也能记笔记、写工作文档。**

- 每个项目就是磁盘上一个文件夹，Markdown + JSON，任何编辑器都能打开
- 体检、基线、账本、伏笔全部在本地用规则算，**0 token、0 网络请求**
- 模型可插拔（DeepSeek / OpenAI / Claude / Ollama / 自定义），换模型不影响内容
- 只有调模型时，正文才会发给你选的服务商

## 三种项目类型

建项目时选一次，之后界面按类型显示不同的工具：

| 类型 | 内容目录 | 用到的功能 |
|---|---|---|
| **小说** | `正文/` + `细纲/` | 全套写作工具：体检、账本、伏笔、人设、八问、开写包、三章诊断、市场调研 |
| **笔记** | `文档/` | 干净编辑器 + 目录树 + 标签 + 搜索 + 快速记录 + AI 对话 |
| **工作文档** | `文档/` | 同上，文案偏工作场景 |

老数据没有 `kind` 字段，一律按小说处理，不用迁移。

**通用能力（三种类型都有）**：嵌套文件夹、全局搜索、标签、快速记录、版本快照与回滚、导出。

## 快速开始

```bash
npm install

# 开发（热更新）
npm run dev

# 类型检查
npm run typecheck

# 构建 + 主进程冒烟自检（会验证核心算法和界面渲染）
npm run build -w @mojiang/desktop
npm run smoke -w @mojiang/desktop

# 打 Windows 安装包（产物在 release/）
npm run build:win
```

要求 Node 20+（当前在 Node 24 上验证过）。

## 目录结构

```
MoJiang/
├── apps/desktop/          Electron 应用（主进程 / 预加载 / 渲染进程）
│   └── src/
│       ├── main/          窗口、IPC、文件服务、日志、密钥存储
│       ├── preload/       contextBridge 白名单
│       ├── renderer/      React 界面
│       └── shared/        三端共享类型
├── packages/core/         纯 TS 能力：切分、六维、词库、基线、账本、伏笔、八问、人设
└── packages/llm/          模型抽象层：统一接口 + 三家实现 + 成本估算
```

`packages/core` 不依赖 Electron 和 Node，将来可以直接做成 CLI 或网页版，不用改代码。

默认在 **`文档/墨匠`**（Windows 上通常是 `C:\Users\<你>\Documents\墨匠`），不在 AppData。

```

│   │   ├── 大纲.md
│   │   ├── 人设/                角色卡（Markdown + 内嵌 JSON）
│   │   ├── 细纲/001.md
│   │   ├── 正文/001.md

│   │   ├── 伏笔.json
│   │   ├── 基线.json            六维 μ±σ
│   │   └── 版本/                自动快照，默认每篇保留 50 份
│   ├── 工作笔记/                笔记项目（kind: "notes"）
│   │   ├── book.json
│   │   ├── 文档/
│   │   │   ├── 周会记录.md      带 frontmatter 标签
│   │   │   └── 会议/11月复盘.md  支持嵌套文件夹
```


## 已经能用的功能

**阶段 0 · 地基**

- Electron 32 + electron-vite + React 18 + TypeScript + Tailwind
- `contextIsolation: true` / `nodeIntegration: false`，预加载只暴露白名单 API
- 所有文件操作在主进程，路径统一过 `assertInsideRoot`，防 `../` 穿越
- 书库：建 / 读 / 删（进回收站）/ 列表 / 恢复
- 章节：建 / 读 / 写 / 删，写前自动快照
- 三栏界面 + 自绘标题栏 + 自动保存（2.5s）+ Ctrl+S

**通用能力（三种项目类型共享）**

- 嵌套目录树，可新建文件夹，笔记按标题命名、小说按 001 编号
- 全局搜索：跨项目搜正文内容，点结果直接跳到那篇文档
- 标签：存在 frontmatter，左栏按标签筛选
- 快速记录：`Ctrl+Shift+N`，一句话存进「收件箱」，不用先建项目
- 版本快照、diff、回滚；导出 txt / md / docx / epub

**阶段 1 · 本地能力（不花 token，仅小说项目）**

- 12 类词库闸：措辞腔调 / 心理套话 / 环境滥喻 / 连接词 / 总结升华 / 句式模板 /
  情绪直述 / 节奏 / 重复 / 对话 / 口语化 / 标点情绪
  - 专有名词豁免（账本主体 + 人设名不算重复）
  - 情绪高点段落的重复降级为提示
  - 按每千字密度容忍，不是出现即报
- 六维基线：句法复杂度 / 修饰密度 / 抽象度 / 动作密度 / 不确定性 / 留白指数
  - μ±σ，偏离 1.5σ 出带
  - 正在检查的章不进取样
- 右侧体检面板：综合分 + 雷达图 + 12 类清单 + 命中明细，改字即刷新
- 编辑器命中行高亮：词库命中的行直接标黄，不用来回对照右侧列表
- **账本视图**：主体状态树、patch 历史、`[[账本|主体|字段|值]]` 标注提取落账、正文与账本冲突提示
- **伏笔视图**：登记 / 提及本章 / 标记回收 / 超期告警（计划超期优先报）
- **人设卡视图**：身份、性格、缺陷、说话方式（句长/口头禅/禁区/称呼）、情绪基线、语用演变；
  OOC 检测与千人一腔检测，台词按名字附近 40 字启发式提取
- **黄金三章诊断**：钩子强度 / 开场节奏 / 冲突密度 / 设定克制 / 字数达标 / 对话占比，前三章一键打分
- **版本历史**：每次保存自动快照，行级 diff 只显示变更点前后 3 行，支持一键回滚（回滚本身也会留快照）

**阶段 2 · 模型接入**

- Provider 抽象层 + OpenAI 兼容 / Anthropic / Ollama 三个实现
- 流式输出（SSE + NDJSON），可中途停止
- API Key 用 Electron `safeStorage` 加密（Windows 走 DPAPI），存在 userData，
  **不进书稿目录**；系统钥匙串不可用时降级为 AES-256-GCM 并提示风险
- 调用前预估 token 和花费，超单章上限先问，超月度上限直接拒绝
- 首次引导 5 步，可全程跳过

**阶段 3 · 写作流**

- 八问大纲状态机：一次一问，没答完禁止生成，跳过记默认值并标黄
- **开写包面板**：16 项取齐情况一览，缺哪项直接给补救动作；
  可复制成提示词，或一键塞进 AI 输入框（补一句指令就能发）
- 版本快照、diff 与回滚

**阶段 4 · 市场调研**

- **自动抓取**：起点 / 晋江 / 七猫 / 飞卢 / 番茄，取各平台榜单前 20
  - 按页面实际编码解码（飞卢是 GBK，不处理会全是乱码）
  - 过滤混进来的章节标题（"第88章 xxx"）
  - 抓到但解析不出时，把原始 HTML 存到 `报告/原始/`，方便日后修解析规则
- **手动录入**：从浏览器复制榜单直接粘贴，认"1 书名 作者"、"书名 | 作者"、制表符分隔
- **报告**：写入 `报告/市场.md`，包含各平台状态、条目、事实观察（书名长度、高频词、数据缺口）
- 只陈述事实，不下选题结论

**实测情况（2026-11，仅供预期管理）**

| 平台 | 结果 | 说明 |
|---|---|---|
| 起点 | 抓不到 | 返回 HTTP 202 + 209 字节的反爬验证页 |
| 晋江 | 部分可用 | HTTP 200，但页面只暴露 6 条书籍链接 |
| 七猫 | 抓不到 | 域名连接失败 |
| 飞卢 | 可用 | HTTP 200 / 404KB，取首页推荐位前 20（不是官方榜单） |
| 番茄 | 抓不到 | 字体混淆 + 需要 JS 渲染 |

所以**手动录入才是日常主力**：抓取只是顺手，抓不到就复制粘贴，数据一样进报告。
程序不会为了"看起来能用"去编数据——抓不到就是 degraded，报告里直接写"数据缺口"。

**阶段 4 · 导出**

- **TXT**：一行一段，带 BOM，记事本打开不乱码
- **按章 Markdown**：正文一章一文件，细纲 / 人设 / 账本 / 伏笔 / 基线一起带走
- **DOCX**：宋体、首行缩进两字、每章分页，A4 页面
- **EPUB**：EPUB 3 + NCX 双目录，mimetype 按规范放在包首且不压缩
- docx / epub 用自己写的 zip 写入器，不引第三方打包库

## 打包

```bash
npm run build:win
```

产物在 `release/`：

| 文件 | 说明 |
|---|---|
| `墨匠-0.1.0-x64.exe` | NSIS 安装包，76 MB，可选安装目录、免管理员权限 |
| `win-unpacked/` | 绿色版，直接跑里面的 `墨匠.exe` |

已经验证过：安装包能构建，打包后的 exe 能启动、渲染界面、跑完三套自检。

**图标**：安装向导、窗口、任务栏都用 `build/icon.ico` / `build/icon-256.png`。
但 **exe 文件本身的资源图标还是 Electron 默认**——因为写入 exe 元数据要 `winCodeSign`，
它解压时会创建 macOS 的符号链接，普通用户权限会失败，而 electron-builder 每次构建的缓存 hash 都不同，
没法预先解压。想要 exe 图标也正确：开 Windows 开发者模式，或用管理员权限打包，
然后把 `electron-builder.yml` 里的 `signAndEditExecutable` 改成 `true`。

**签名**：目前没有代码签名证书，用户第一次运行会有 SmartScreen 提示，需要点"更多信息 → 仍要运行"。

## 几个实现决策（和规划书不同的地方）

| 规划书 | 实际 | 原因 |
|---|---|---|
| `keytar` 存 Key | Electron `safeStorage` | keytar 是原生模块，装不上就崩，每个 Electron 大版本要重编；safeStorage 是官方方案，安全等级相同且零编译 |
| shadcn/ui | 手写 Tailwind 组件 | 初版不值得为几个按钮装十来个 radix 包；视觉语言一致，后续可替换 |
| `packages/core` 独立编译 | 独立目录 + 源码 alias 直引 | 省掉一次构建同步；代码本身仍不依赖 Electron，要独立发 npm 包时加个 tsc 即可 |
| 中文分词库 | `Intl.Segmenter` | 内置 API，零依赖零词表，切句切词够用 |

## 自检

`npm run smoke -w @mojiang/desktop` 会做三件事：

1. 主进程启动、数据目录创建
2. 用一段故意写得很差的样例正文跑一遍 12 类检测 / 六维 / 基线 / 账本冲突 / 黄金三章 / 八问闸门
3. 人设卡 Markdown 往返、台词提取、OOC、千人一腔、伏笔超期、中文账本路径 patch
4. 导出结构：docx 的 zip 签名与 `word/document.xml`、EPUB 的 mimetype 必须在包首且未压缩
5. 榜单文本解析（三种常见复制格式）与报告生成
6. 检查渲染进程没有白屏、`window.api` 已注入

结果写在 `文档/墨匠/日志/` 里。

## 隐私

- 不上传任何数据，除了调模型时的 prompt
- 完全离线模式：接 Ollama，本机跑模型
- 数据不是人质：整个目录可以直接拷走，或者用别的编辑器打开
- 卸载时不会删「文档/墨匠」，书稿默认保留
